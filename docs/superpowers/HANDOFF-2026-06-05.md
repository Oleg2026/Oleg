## 1. Зачем это всё (проблема)

Основной autoXRAY (TCP VLESS REALITY/XHTTP) **стал давать сбои на мобильных операторах**.
Симптом: соединение работает несколько минут, потом рвётся, восстановление случайное —
от минуты до часа. Это **не баг скрипта**, а поведенческая блокировка мобильного ТСПУ:
DPI классифицирует туннель по поведению/таймингам и держит в «чёрном окне».

Подтверждённая механика (net4people/bbs#490): к иностранному IP по TLS соединение «замораживается»
после ~25 пакетов / ~16 КБ. Плюс поведенческая классификация самого REALITY/XHTTP-потока.

**Решение:** UDP-протоколы (AmneziaWG, Hysteria2) под эти TCP-правила не попадают. Поднимаем их
на **отдельном** VPS как параллельный путь. Старые REALITY-конфиги остаются запасными.

## 2. Что сделано

- **`autoXRAY-udp.sh`** (корень репо) — новый установщик на отдельный Debian 12 VPS:
  - nginx + certbot: selfsteal-сайт на **TCP 443** + хостинг страницы подписки + общий TLS-серт.
  - **Hysteria2**: UDP 443, Salamander-обфускация, **port-hopping** 20000–40000 (iptables REDIRECT),
    версия запиннена `v2.6.0`, берёт серт из файлов certbot.
  - **AmneziaWG**: UDP 51820, обфускация (Jc/Jmin/Jmax/S1/S2/H1–H4), модуль ядра DKMS с
    фолбэком на userspace `amneziawg-go`.
  - NAT MASQUERADE для выхода клиентов в интернет.
  - HTML-страница подписки с QR и кнопками «Add to HAPP» для обоих протоколов.
- **Ревью пройдено** (соответствие спеке + качество кода). Исправлена **критичная утечка**:
  клиентский AmneziaWG `.conf` лежал по предсказуемому URL `/awg-client.conf` (любой по `curl`
  скачивал приватный ключ) → теперь случайное имя файла + права 644 (читаемо nginx).
- **README**: добавлен UPD6 и раздел «UDP-сервер против мобильного DPI».
- Локальная проверка: `bash -n autoXRAY-udp.sh` — чисто. **Установщик на VPS НЕ запускался.**

## 4. Что осталось сделать (по порядку)

### Шаг A. Открыть Pull Request (опционально)
Ссылка: https://github.com/Oleg2026/Oleg/compare/master...feat/udp-installer
(или сразу слить ветку в master локально, если PR не нужен).

### Шаг B. Подготовить домен и VPS
1. Арендовать **отдельный** чистый Debian 12 VPS (желательно с поддержкой UDP — уточнить у хостера!).
2. Завести **A-запись** поддомена (например `udp.<домен>`) на **IP этого нового VPS**.
   `udp.вашДОМЕН.com` в примерах — это ПЛЕЙСХОЛДЕР, подставить свой реальный поддомен.
3. Дождаться прорастания DNS (15 мин – час; проверка: xseo.in/dns).

### Шаг C. Деплой (главная проверка — Task 11)
Скопировать скрипт на VPS и запустить от root:
```bash
scp autoXRAY-udp.sh root@<IP-VPS>:/root/
ssh root@<IP-VPS>
bash /root/autoXRAY-udp.sh udp.<вашдомен>     # подставить реальный поддомен
```
Ожидаемо в конце — блок «Финальная проверка»: `nginx`, `hysteria-server`, `awg-quick@awg0` = RUNNING.

### Шаг D. Приёмочный чек-лист
- [ ] Все три сервиса RUNNING; сертификат получен.
- [ ] `ss -uangp | grep -E ':(443|51820)'` — Hysteria2 на UDP 443, AmneziaWG на UDP 51820.
- [ ] `curl -kI https://udp.<домен>/` → 200, отдаётся сайт-маскировка.
- [ ] Открыть страницу подписки `https://udp.<домен>/<случайный>.html`, импортировать в Happ:
  - [ ] Hysteria2 → подключиться → есть интернет, IP сервера.
  - [ ] AmneziaWG → подключиться → есть интернет.
- [ ] Подержать 15–20 мин под нагрузкой на **мобильном интернете оператора** — убедиться,
  что нет «5 мин вкл / 5 мин выкл», в отличие от TCP-REALITY.

### Шаг E. Если UDP режется/не идёт
- Проверить, что хостер пропускает UDP и фаервол открыт: `51820/udp`, `20000-40000/udp`.
- Расширить диапазон port-hopping в `/etc/hysteria/config.yaml` + правиле iptables, затем
  `systemctl restart hysteria-server`. Можно сменить `AWG_PORT`.

  `feat/udp-installer`, push (см. нюанс в §3).
